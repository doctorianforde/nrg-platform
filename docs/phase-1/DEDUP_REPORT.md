Generated by `npx tsx scripts/dedup-bank.ts --report` on 2026-10-17. Staging only (`kwhaqhhwqykckarjbdod`). Verdicts: `docs/phase-1/dedup-verdicts.json`. Reviewer brief: `docs/phase-1/DEDUP_BRIEF.md`.

## Method

**Why.** The token-overlap check in `fix-option-cues.ts` (stop-worded Jaccard ≥ 0.5) catches reworded duplicates but
not rewritten ones, so Jade would review the same scenario two, three or ten times. This pass compares meaning instead.

**Scope.** All 1,990 AI items not already retired (`ai:*`, source `ai_generated`), compared with each other, with all
516 of Jade's questions (`jade:*`) and with the 4,623 live/pending prototype-import questions (`proto:*`). Jade's and
prototype items are never changed. Case-study questions are out of scope.

**Embeddings.** Local, no paid API: Ollama with `nomic-embed-text` and `mxbai-embed-large`, three text recipes each
(stem; stem + correct answer; stem + all options + answer). Vectors are cached in `scripts/data/dedup/emb-*.json`
(gitignored, ~90 MB each), keyed by source_id and a hash of the text, so reruns only embed changed items.
Raw cosines sat in a narrow 0.85–0.97 band for every pair (every item is "a nursing exam question"), so vectors are
**centred on the bank mean** before cosine; this spreads the scores so a threshold means something.

**Choosing model and recipe.** Scored against the 14 duplicate pairs earlier reviewers had already recorded in
review_notes ("Duplicate of …"): how often the recorded partner is the item's nearest neighbour.

| Model / recipe | partner is nearest neighbour | partner in top 5 |
|---|---|---|
| nomic / stem | 5/14 | 10/14 |
| nomic / stem + answer | 7/14 | 12/14 |
| nomic / stem + options | 7/14 | 12/14 |
| mxbai / stem | 6/14 | 11/14 |
| **mxbai / stem + answer (used)** | **9/14** | **12/14** |
| mxbai / stem + options | 7/14 | 12/14 |

The gold set is small and half of it pairs an un-rewritten original with a rewritten item, so the threshold was then
set by reading pairs, not by the gold set.

**Threshold (chosen for recall).** Before any judging, random AI-AI pairs were read per cosine band (strict standard):
0.72–0.78 about 1 in 3 real duplicates, 0.65–0.72 about 1 in 2, 0.58–0.65 about 1 in 14. Precision only collapses
below 0.65, so the AI-AI threshold is **0.65**. Cross-pool: **0.60** against Jade (these decide retirements, so recall
matters more) and **0.70** against the prototype import (report only). The table below gives the measured precision
per band after judging.

**Clusters.** An edge is kept only if one item is among the other's 3 nearest AI neighbours (stops generic
"four clients / delegation" hubs chaining whole topics), then union-find with a size cap of 12: an oversized component
is re-split at +0.01 until every piece fits. 2,560 pairs ≥ 0.65 → 1,939 kept → 267 clusters (1,330 items). The 40
items the cap split off into no cluster were judged separately against the items they linked to (O001–O040).

**Judgement.** Every cluster and cross-pool entry was read and judged against `docs/phase-1/DEDUP_BRIEF.md`: a
duplicate is the same clinical scenario **and** the same tested concept and answer; same topic with a different
decision point, calculations with different numbers, and prioritisation/delegation items with different clients or
tasks are distinct. 15 reviewer subagents did the 19 main batches, the coordinator judged the 40 orphans and
spot-checked the results (below). Keeper rule: approved/live > teacher-reviewed > better quality (full rationales,
sound key, clearer stem) > older. An AI item that duplicates a Jade question is retired in favour of Jade's original,
except Jade's `nrg-qbank-starter-56` set (never live, known miskey pattern), which is reported only.

**Precision spot-check of the result.** 30 random AI-AI retirements read against their keepers: 30/30 genuine
duplicates (3 close calls: asthma "silent chest" vs "diminished breath sounds", two professional-development
items, two chronic-disease follow-up items). 15 random AI-vs-Jade retirements: 15/15 (2 close calls: post-op bleeding
"recognise" vs "act", magnesium "what is it for" vs "first-line drug").

**Applying.** Retirement follows the review-bank `retire` convention exactly: `review_status = 'rejected'`,
`is_active = false`, and a review_notes line `[dedup-v1 2026-10-17] RETIRED: Duplicate of <keeper>, which is kept
(<reason>).` Every changed row was first copied to staging table `_backup_dedup_questions_20261017` (RLS on, no
policies). Guards: only `ai:*` rows that are inactive and not approved are touched; the run is idempotent (a second
`--apply` finds 0 to do). Rollback: `scripts/sql/dedup-v1-rollback-staging.sql` (tested inside a rolled-back
transaction: restores all 610 rows and leaves 0 dedup notes).

**Rerun.** `npx tsx scripts/dedup-bank.ts --candidates` → `--batches` → reviewers write `*.out.json` →
`--merge` → `--apply [--commit]` → `--report` → `--prod-sql`. Cluster ids are deterministic for an unchanged bank.

**Prod.** `data/review/prod-port/dedup-v1-prod.sql` (gitignored, next to `ai-port.sql`): the same 610 retirements
keyed by source_id, with its own backup table and `dedup-v1-prod-rollback.sql`. **Run it only after `ai-port.sql`**:
its guards expect the ported AI rows (inactive, pending). Dry-run on staging in a rolled-back transaction: 610 × n = 1.
Not run on prod.

  found roughly 1 in 14 real duplicates there, so on the order of 40 more AI-AI duplicates probably remain. Also, and a few duplicates whose partner was outside a cluster's link
  list were noted by reviewers but not acted on (e.g. J032 vs renr-100-original:q30, P168 vs professionalism:7257).

  probably find more AI items to retire in favour of Jade originals.
- The 14-pair gold set is small; precision figures come from reading pairs, not from a labelled benchmark.
- Keepers were mostly decided by age because nearly every AI item is pending, unreviewed and fully rationalised.
